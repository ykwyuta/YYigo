# いきがみえる囲碁

スマホで遊べる、**ルールを覚えていない子どもでも遊べる**囲碁です。
石をタッチすると「いき（呼吸点）」が光り、アタリの石には数字が付きます。置く前に「置いたらどうなるか」が見えるので、ルールを覚える前から一局打ちながら覚えられます。

[うごきがみえる将棋（YYshogi）](https://github.com/ykwyuta/YYshogi) と同じ考え方・同じ構成で作っています。ブラウザだけで動く静的サイトです。ビルドもサーバーも要りません。Cloudflare（Workers の静的アセット配信）でそのまま公開できます。

- **2つのルール**
  - **いしとり**：先に決めた数（1・3・5・10こ）の石を取った方の勝ち。はじめての子ども向け
  - **ふつうの囲碁**：中国ルール（盤上の石＋地）で数える。コミ 6.5（置き碁は 0.5）
- 盤の大きさ：7路・9路・13路・19路
- CPU 対戦（はじめて／よわい／ふつう／つよい、くろ・しろ・おまかせ）。「はじめて」は取れる石は必ず取りますが、それ以外は半分以上の手を適当に打つので、子どもでも勝てます
- ふたりで対戦（1台のスマホを交互に使う）
- ハンデ（置き碁）：9路まで 2〜5子、13路・19路は 2〜9子
- **いしとり もんだい 30 問**（1手 10・3手 12・5手 8）。全問に解説つき
- 対局は自動保存。ブラウザを閉じても続きから遊べます
- ホーム画面に追加するとアプリのように全画面で使えます

## 子ども向けのおたすけ機能

| 機能 | 内容 |
| --- | --- |
| おく前に たしかめる | 空いている点をタッチすると、うすい石と「置いたらどうなるか」（取れる石・アタリになる石・置いた石のいきの数）を表示。もう一度タッチで置きます（せっていで 1回タッチに変更可）。 |
| いき が見える | 石をタッチすると、その石（つながった石全体）のいきが緑の●で光ります。相手の石はオレンジ。 |
| いきの かず | いきが 1〜2 の石に数字。1（アタリ）は赤く点滅します。 |
| とれる ところ | 置くと相手の石が取れる点に赤い わ。 |
| あぶないマーク | 置くとすぐ取られそうな（いきが 1つしかない）点に「!」。 |
| アタリのお知らせ | 自分の石がアタリになると画面が赤くなり「アタリ！」と表示。相手をアタリにしたときも知らせます。 |
| おけない ところ | 自殺手・コウの点は最初から置けず、タッチすると理由を説明します。コウの点には「コ」の印。 |
| ヒント | CPU がおすすめの手を教えてくれます（光った点をタッチするだけ）。 |
| まった | 何手でも戻せます。負けた後や数えた後でも「まった」で戻ってやり直せます。 |
| いまの じんち | メニューから、今の形勢（どちらの地になりそうか）を盤に表示。 |
| かぞえる | 2人つづけてパスすると、死に石を自動で判定して地を表示。違うときは石をタッチして直してから「これで かぞえる」。 |

「ルール」ボタンでは、石の置き方・いき・取る・アタリ・つながり・すみとへり・置けないところ・コウ・地・コミを図つきで説明します。

## いしとり もんだい

画面上の「いしとり もんだい」ボタン（またはメニュー）から、30 問の問題集を遊べます。

- くろの番。しるし（△）の付いたしろい石を、決められた手数で取ります。
- しろは一番長く逃げる手を打ってきます。
- 手数内に取れない手を打つと、しろが逃げて「ざんねん」。「まった」で戻ってやり直せます。
- 「ヒント」で次の正解の手が光ります。「こたえを みる」で解説・まちがえやすい手（とその逃げ方）を見たり、正解手順を盤に並べたりできます。
- クリアした問題には ★ が付き、記録は自動保存されます。

### 問題の作り方と検証

1手問題は手で作りました。3手・5手は手で作った「へりへ おとす」「うってがえし」のほかは、`tools/gen-tsumego.js` でランダムな局面から候補を作り、ソルバー（`js/tsumego.js`）で次の条件を満たすものだけを残して、その中から選んで解説を書いています。

- ちょうど N 手で取れて、それより短い手数では取れない
- 初手の正解がひとつだけ。しろがどの自然な受け（いきに伸びる・くろをアタリにする）を選んでも、くろの正解はいつもひとつ
- くろの石に無駄がない（どれか 1つを取り除くと N 手では取れない）。しるし以外のしろの石にも無駄がない

ソルバーは、しるしの石から 2マス以内の空き点と、まわりのいきの少ないくろの石のいき（しろはパス＝手抜きもふくむ）を読み切ります。`node test/tsumego.test.js` で全問を確かめています。

```sh
node tools/gen-tsumego.js 3 20 42 7 > candidates.json   # 3手問題の候補を 20 個（seed 42・7路）
NET=1 node tools/gen-tsumego.js 5 10 1 7                 # 初手がアタリでない（ゲタなど）5手問題
node tools/analyze.js                                     # 全問の最短手数・正解・本手順を表示
```

## ルール

- 黒と白が交互に、線の交わる点に石を置きます（置き碁では白から）。
- 縦横のとなりの空き点（いき）を全部ふさがれた石は取られます。
- 自殺手（置いた石のいきがなくなる手。ただし相手の石が取れる場合は除く）は禁止。
- コウ：1つ取られた直後に取り返して同じ形に戻す手は禁止（同形反復は単純なコウのみ判定）。
- いしとり：先に決めた数を取った方の勝ち。2人つづけてパス、または手数の上限で、取った数の多い方の勝ち（同じなら引き分け）。
- ふつうの囲碁：2人つづけてパスで終局。死に石を取り除き、盤上の石＋自分の石だけに囲まれた空き点を数えます（中国ルール）。白にコミ 6.5（置き碁は 0.5）。手数の上限（盤の点の数 × 3）でも数えます。

## 遊びかた

1. 石を置きたい点をタッチ。うすい石と、置いたらどうなるかが出ます。
2. もう一度タッチすると置きます。
3. 石をタッチすると「いき」が見えます。数字の 1 はアタリ！
4. 迷ったら「ヒント」、間違えたら「まった」。

## Cloudflare で無料公開する

Cloudflare Workers の静的アセット配信を使います。ビルドは不要で、静的ファイルへのリクエストは無料プランでも無料・無制限です。設定はリポジトリに入っている `wrangler.jsonc` / `.assetsignore` / `_headers` だけです。

### 方法 A：GitHub と連携して自動デプロイ（おすすめ）

1. ゲーム本体と `wrangler.jsonc` が入ったブランチを、Cloudflare がビルドする本番ブランチにしておく（このリポジトリの既定ブランチは `master`。ここにマージするか、Cloudflare 側の本番ブランチを変更する）。
2. [Cloudflare ダッシュボード](https://dash.cloudflare.com/) にログイン（無料アカウントで OK）→ **Workers & Pages** → **作成（Create）** → **リポジトリをインポート（Import a repository）**。
3. GitHub を連携して `YYigo` を選ぶ。
4. 設定はそのままで構いません。
   - ビルドコマンド：空欄
   - デプロイコマンド：`npx wrangler deploy`（既定値）
   - ルートディレクトリ：`/`
5. **デプロイ** を押すと `https://yyigo.<あなたのサブドメイン>.workers.dev` で公開されます。

以降は本番ブランチに push するたびに自動で再デプロイされます。

> **`Could not detect a directory containing static files` で失敗する場合**
> Cloudflare がビルドしたブランチに `wrangler.jsonc` が入っていません（README だけの `master` をビルドしたときなど）。ゲームを含むブランチをマージするか、Worker の **設定 → ビルド → ブランチ管理** で本番ブランチを切り替えてから再デプロイしてください。

### 方法 B：手元のパソコンからコマンドで公開

```sh
npx wrangler login    # 初回のみ。ブラウザで Cloudflare にログイン
npx wrangler deploy   # 公開（URL が表示される）
```

公開前に手元で確認したいときは `npx wrangler dev` で http://localhost:8787 に立ち上がります。

### 公開に関係するファイル

| ファイル | 役割 |
| --- | --- |
| `wrangler.jsonc` | Worker 名（`yyigo`）と、リポジトリのルートを静的サイトとして配信する設定。 |
| `.assetsignore` | 公開しないファイル（README・テスト・設定ファイルなど）。 |
| `_headers` | キャッシュとセキュリティ関連の HTTP ヘッダー。 |

## ファイル構成

```
index.html             画面
css/style.css          見た目（スマホ縦向きを基本に、広い画面では2段組み）
js/rules.js            ルールエンジン（着手・取り・自殺手・コウ・置き石・数える）
js/ai.js               CPU 思考（モンテカルロ木探索 UCT + RAVE。制限時間で打ち切り）・形勢判断・死に石の判定
js/worker.js           CPU の思考を Web Worker で動かす（画面が固まらない）
js/tsumego.js          いしとり もんだいのソルバー（正解判定・しろの応手・ヒント・まちがえやすい手）
js/tsumego-data.js     いしとり もんだい 30 問と解説
js/ui.js               描画と操作（おたすけ表示・ヒント・まった・数える・保存）
manifest.webmanifest   ホーム画面に追加したときの設定
icons/                 アイコン
test/                  Node.js で動くテスト（公開はされない）
tools/                 問題の生成・分析ツール（公開はされない）
```

ルールエンジンは DOM に依存しない純粋な関数で、`apply` は常に新しい局面を返します。CPU は高速化のため、周りに枠を付けた盤と「疑似呼吸点」で連を管理する専用の盤（`AI.FastBoard`）でプレイアウトします（ルールエンジンと同じ結果になることをテストで確認）。`index.html` をファイルとして直接開いた場合など Web Worker が使えない環境では、CPU は画面側で考えます。

```js
require('./js/rules.js'); require('./js/ai.js');
let s = Engine.newGame({ size: 9, rule: 'territory' });
const st = { size: s.size, board: s.board, turn: s.turn, ko: s.ko, caps: s.caps, rule: s.rule, komi: s.komi, last: -1 };
s = Engine.apply(s, AI.think(st, 'normal'));
console.log(s.kifu); // [ '●5の五' ] など
```
